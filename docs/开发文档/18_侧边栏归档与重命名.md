# 侧边栏会话归档与重命名落地记录

日期：2026-10-14 · 状态：已实现（Playwright 端到端验证通过）
背景：dsh 设计上没有"删除会话"（日志 append-only），原生只有重命名/fork/归档；
清水扁平侧边栏最初替换原生列表时把行操作全丢了。本次补齐两个行操作，全部走
dsh 原生 RPC，零 dsh 改动。

## 一、功能

| 操作 | 交互 | 通道 |
|---|---|---|
| 重命名 | 行 hover 出 ✎ → 行内输入框（预填当前标题）→ Enter/失焦提交，Esc 取消 | `sessions.binding(id).session.rename(title)`（`session.rename` 1:1） |
| 归档 | 行 hover 出 🗄 → 点击变"确认归档？"（3 秒自动复位）→ 再点提交；归档集为 registry 全局持久集合 | `workspaces.archiveSession(id)`（`workspace.archiveSession`） |

- 列表按 `useWorkspaces(s => s.archivedSessionIds)` 过滤（根作用域标准成员，
  `connect()` 无条件拉取 workspaces 基线，不依赖原生 WorkspaceBrowser 是否在渲染）。
- 归档=隐藏不删日志：会话文件仍在 `~/.dsh-qingshui/sessions/`，dsh 暂无 unarchive
  UI，故两步确认是刻意的防误触。
- 渲染优先级：`title ??（blank ? 新对话 : displayTitle）`——`title` 字段只在
  显式命名/自动命名后存在，`displayTitle` 是 cwd 派生的兜底名。此前
  `blank ? 新对话 : …` 会把"改过名的空白会话"错误显示回"新对话"（已修）。

## 二、验证（2026-10-14 本地）

- `pnpm test:plugin` 52/52（session-actions 新增 archive/rename 接线 4 案）。
- Playwright 实测：空白会话改名后**即时可见**（修复前不可见）；重命名往返非空白会话
  成功；两步归档后行消失；composer 无回归。

## 三、已知边界

1. 无 unarchive 入口（dsh 上游已知限制）；如需恢复，操作 storages 中 workspace
   registry 的 archived 集合后重启 web。
2. 归档的确认窗口 3 秒、不可配置（协议常量）。
