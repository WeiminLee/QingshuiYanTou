# EV 引用交互化（悬停预览 + 点击看证据）落地记录

日期：2026-10-14 · 状态：已实现（本地端到端验证通过；后端短 ID 前缀解析已改待 chemagent 部署）
需求来源：owner 反馈——回复正文里的 `EV:xxxx` 引用应可点击/悬停并展示原始证据。
相关代码：`plugins/qingshui/src/client/ev-*.ts(x)`、`plugins/qingshui/src/ev-route.ts`、
`backend/app/knowledge/evidence_service.py`。

## 一、目标与形态

| 交互 | 行为 |
|---|---|
| 正文 `EV:<hex>` | 自动提升为**可点击 chip**（等宽、深seek蓝、下划线 hover） |
| 悬停 chip（250ms） | chip 附近弹出**证据预览卡**：标题/来源类型/来源/日期/摘录（4 行折叠）/PID/原文 PDF 链接 |
| 点击 chip | 钉成**居中大卡**（全摘录 10 行折叠 + 展开全文），ESC/点击遮罩关闭 |
| 加载失败 | 错误提示 + 短 ID 说明 + 重试按钮 |

对**历史会话同样生效**（变换发生在渲染层，不依赖模型输出格式）；工作区产物文件提及
（行内代码文件链接）优先级不变。

## 二、架构（零 dsh 改动，全部落清水插件层）

```
MarkdownText(ui-primitives, 现成 fileMentions 缝隙)
   ▲ text 先过 evCiteTransform：裸 EV:hex → 行内代码 token
   │   — fence/既有行内代码跳过；幂等；fence 状态机逐行处理
   ▲ fileMentions 解析器：产物链接(docstring 语义)优先，EV token 兜底
QsAssistantStepView(ev-view.tsx)
   └ 影子注册 conversation.chat.node key='assistant-step' priority=-1
      （与 conversation 根影子同一"低优先者胜"机制；崩溃自动让位回原生渲染器）
EvCiteLayer(挂 ResearchConversationRoot，portal 到 body)
   └ 悬停由助手消息容器内 mouseover/mouseout 委托识别 chip（button 文本整值匹配）
   └ 状态经模块级 ev-cite-store（useSyncExternalStore 消费）
```

**数据通道**：浏览器 → 同源 `GET /qingshui/evidence/<id>`（`webServer` prefix 路由，插件
Node 半边 `ctx.inject(['webServer'])` 挂载，仅 web profile 激活）→ 插件 knowledge-client →
（SSH 隧道）chemagent `GET /api/v1/knowledge/evidence/{id}`。**API key 只留宿主进程**，
浏览器零凭据。路由按 /api 通道同款姿态做 Host 环回 + Sec-Fetch-Site 防护
（`isLoopbackHostRequest`），坏 ID 400、未配置 503、上游 404/错误分型 404/502。

## 三、短 ID 前缀解析（关键实测发现）

实测会话证实：**模型在对话正文经常把 EV ID 缩写为 SHA256 前缀**（16-hex，owner 示例为
8-hex），且全文完整 ID 未必出现在同一会话内——正文引用的前缀**无法**从转录还原。
因此：

- `EvidenceService.get_evidence` 增加前缀回退：精确 miss 且 `EV:[0-9a-f]{8,63}` 时按
  `^前缀` 正则取 id 升序第一条（16-hex 前缀碰撞概率 ~2^-64，可忽略）。
- 附带收益：**模型自身的 `fetch_evidence(EV:短id)` 调用同样被修复**（此前这类调用 404）。
- 本地测试：`backend/tests/test_evidence_service.py` 10 passed（新增 2 案）。
- ⚠ 待部署 chemagent（build backend + up -d backend）后生效；部署前短 ID 悬停显示
  证据未命中提示，完整 64-hex 引用不受影响。
