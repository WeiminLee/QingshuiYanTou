# 预期差的理解与设想（用户观点记录 · 2026-09-17）

> 本文记录项目 owner 对"预期差"的定义与产品设想，作为后续设计依据。
> 性质：**需求方原始观点记录**，非技术结论；技术推导见《检索架构与预期差路线调研-2026-09-17.md》与《findings判断台账设计草案-2026-09-17.md》。

---

## 一、核心定义：预期差不是"相对某个基线的偏离"

> "这种预期差不是对于某个基线而言的。"

预期差的实质是**边际变化 / 状态演进**本身，而不是"实际值 − 预期值"的差值。因此不需要引入卖方一致预期之类的基准数据。

## 二、预期差的典型形态（owner 列举）

> "我的设想是：在互动易中，对于产线进展的描述中递进式表达；产品毛利率在公告中的增加；产品认证进展中措辞的变化；行业利好新闻的发布；关联公司公告中的大订单签订；等等。这些都是预期差。"

归纳为五类：

| # | 形态 | 说明 |
|---|---|---|
| 1 | **互动易 · 产线进展的递进式表达** | 同一主体对产线状态的表述逐次推进 |
| 2 | **公告 · 产品毛利率的增加** | 数值指标的边际提升 |
| 3 | **产品认证进展中措辞的变化** | 同一维度的表达强度/确定性发生改变 |
| 4 | **行业利好新闻的发布** | 行业层面的新增正向事件 |
| 5 | **关联公司公告中的大订单签订** | 通过关联/产业链主体传导过来的事件 |

（"等等"——以上为形态示例，非封闭枚举。）

## 三、能力定位：**核心是判断，不是检索**

> "我们要做的不是从到有的检索，核心落在判断。"

- 检索/召回只是喂料；**判断才是核心能力所在**。
- 系统的价值体现在 agent 能否从召回的信息中**主动识别出上述变化**。

## 四、agent 的工作方式设想

> "如果我要求 agent 对某个公司分析，那么 agent 本身需要能够在召回的信息中主动去挖掘这些。"

两种路线的取舍：

| 路线 | 描述 | owner 评价 |
|---|---|---|
| **A. 预先维护、被动取用** | 先维护一套状态/结论，agent 从中被动读取 | "这是一种后处理、被动策略" —— 不够，不是核心 |
| **B. task 时主动挖掘**（owner 倾向） | 在完成用户 task 的过程中，**在核心思考中**，**根据一个新闻点做关联挖掘** | "**才是核心能力所在**" |

> "或者是我们更为现实一点：在完成用户的 task 的时候，在核心思考中，去根据一个新闻点做关联挖掘 —— 才是核心能力所在，包括挖掘之后的维护。"

要点：
- **触发**：用户 task（如"分析某公司"）或**一个新闻点**。
- **位置**：发生在 agent 的**核心思考过程**里，而非独立的离线批处理。
- **范围**：不只是读新闻，而是**关联挖掘**（顺着新闻点把相关的都挖出来）。

## 五、"维护"的定位

> "包括挖掘之后的维护。"

- 维护**不是**独立的后处理管线，而是**挖掘之后的自然沉淀**——挖掘是主动的，维护随之而来。
- 换言之：先有 agent 的主动判断，再把判断沉淀下来；而不是先建一套东西等着被动使用。

## 六、对现有技术栈的态度

> "其实我们完全可以依赖于现有的 agentic search 技术去做这件事。"

- 倾向直接依托现有 agentic search 能力实现，不额外自建重型的抽取/图谱管线。

---

## 七、由此推导的技术含义（记录者整理，待 owner 确认）

1. **"主动挖掘"需要历史对照**：要判断"递进/变化/首次"，agent 必须能拿到该主体该维度的**过往表述**；否则只能看到孤立新闻。→ 需要一个按 (主体, 维度) 检索历史的入口。
2. **挖掘需要可沉淀**：判断完成后要能被记录与复用（即 owner 说的"维护"），否则每次从零读新闻，无法判断"新"。
3. **广度盲区**：纯 task-time 挖掘只能覆盖"用户问到的"；若要发现"用户没想到的公司/机会"，仍需廉价的全市场触发器。
4. **判断的可比性**：同一事实在不同时间由 agent 判断，需要保证口径可比较（阶梯参照、证据留痕）。

---

## 八、待明确的问题

1. 预期差的判定由 agent 完全自主，还是给定维度清单（产线/认证/订单/毛利率/行业…）？
2. "关联挖掘"的关联范围：仅产业链上下游，还是包含同业、客户、股东、概念板块？
3. 挖掘结果是否需要**跨主体、跨 task 复用**？若需要，以什么粒度沉淀？
4. 反向预期差（措辞弱化、进展延后、指标恶化）是否同等重要？
5. 是否需要"发现用户没问到的"能力（广度触发器）？优先级如何？
6. 判断的交付形态：结论文字 + 证据引用，还是需要量化排序？
