# PDF 解析库对比实验（2026-09-01）

## 样本与环境

- 样本：公告 `12541`，7,794,039 bytes，`002553.SZ`
- 节点：`lwm-server-d`，`/opt/conda/bin/python`
- 指标：整文件文本提取耗时、输出字符数、是否在限定时间内完成

## 实测结果

| 库 | 结果 | 备注 |
|---|---:|---|
| PyMuPDF | 3.603 s，594,874 字符 | 成功，稳定完成 |
| pdfplumber | >20 s 未完成（timeout） | 不适合整文件默认路径 |
| pymupdf4llm | 先前实测触发 ONNX Runtime，超过数分钟 | 适合显式复杂版面任务，不适合默认路径 |
| pypdf | 未完成完整计时 | 作为纯文本 fallback，版面能力弱 |

## 结论

生产默认使用 PyMuPDF；表格页面按启发式检测后再路由到 pdfplumber；复杂版面按需显式启用 pymupdf4llm，并设置页面上限与超时。pypdf 仅保留为损坏/兼容性 fallback，不作为主解析器。

本实验已经验证：7.8 MB PDF 的异常耗时来自重型结构化版面分析路径，而不是下载或 GPU 不可用。
