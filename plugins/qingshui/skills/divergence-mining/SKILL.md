# 预期差挖掘（Evidence-first）

## 定义（硬约束）
预期差 = **状态演进 / 边际变化**本身，不是「实际值 − 一致预期」。
开放信息和新闻表面是表面句，先写下来是为了删掉。用户看见的是删完之后仍能落到证据的那一层。问法见下面的算子，清单不封闭。
不要引入卖方一致预期基线。判断必须能落到 `evidence_id`（`EV:…`）。

## 触发
用户要求板块/公司预期差、深度基本面挖掘、是否充分定价。

## 流程（先探索后承诺）
1. **横向**：`mcp__qingshui_data__compare_metric(dimension, scope=板块词)` → 表「主体 | 数值 | 期间」，保留 evidence_id
2. **层次**：`rollup_metric(parent="营收"|相关粗标尺)` → 子指标与命中量
3. **传导**：`propagate_along(start=板块词)` / `related_nodes` → 指标/阶段/公司共现面
4. **纵向**：挑 1–2 个有代表性的主体 `metric_trend(subject, dimension)` → 时间线状态演进。返回的 `acceleration` 已给出 d1、d2、a。用这个字段，不要心算。
5. **二阶导**：先写出表面句（开放信息、新闻表面、水平值、「还在上台阶」），然后删掉。用算子往下问，没有证据的跳过，不许凑满。清单不封闭。算子包括：加速度（d1 = y2 - y1，d2 = y3 - y2，a = d2 - d1；`status` 不是 `ok` 时写「二阶导不可计算」，点数不足只说明加速度算不出，然后继续）、拆因（价、量、结构、一次性）、原理、传导与「然后呢」、供给响应、言数不符、外部基准、识别差、反身。去掉「变化的变化」之后仍然成立的句子不进入结论。没有新的一层是合格结论。此时不铺水平表。每条留下的判断写一句证伪；写不出就标「依据不足」，不升级成判断。
6. **验证**：对关键判断点 `mcp__qingshui_data__fetch_evidence(EV:…)`；语义搜索仅冷启动

## 沉淀（挖掘之后的维护——判断可复用）
分析完成后把结论沉进判断台账，下次分析先查台账、水位线内不重复断言旧闻：

1. **先查**：`mcp__qingshui_data__history_findings(subject=主体, dimension=维度)` → 已有观察时间线 + 判断 + 当前水位线（max_level）
2. **对照**：本次新观察 vs 水位线。表面句不沉淀。`write_finding` 的 judgment 写过了删句的那一层；水位里已经有同一句的，只引用 finding_id，不重复沉淀
3. **观察点**：把本次句级锚定的原始表述/指标点写入 `write_observation`（带 stage_raw/level 或 metric_value）→ 返回 `is_new_level`
4. **判断**：过了删句、相对水位是新的、并且写得出证伪或标明依据不足时 `write_finding`。只复述表面句的，不落笔：
   - `kind`：progression（递进）| regression（恶化）| new_event（新增事件）| association（关联传导）| divergence（矛盾）
   - `supports`：本分析的 EV 句锚 `[{evidence_id, span_start, span_end}]`（硬闸门：伪造/越界会拒写）
   - `to_state`：`{level, stage}` 落归一化阶梯；`judgment` 一句话，写删完之后的那一层，不写新闻标题，不写「站上新台阶」
   - 幂等：同支撑集重复写入自动合并，重跑分析安全
5. **数值型观察**：`write_observation` 带 `metric_value: {num, unit, period, metric}`（如毛利率/订单额）→ 返回
   - `is_new_extreme`（区间外=数值新台阶，只是一阶）与 `delta`/`delta_pct`（环比上一披露值，即 d2）。judgment 仍写 a = d2 - d1
   - `same_period_restated=True` 是同期间修正披露，**不判递进**
   - 新高/新低 → progression/regression 的方向由指标语义定（毛利率新低一般是 regression，成本率新低是 progression）
6. **修正旧判断**：结论推翻或收窄先前判断时 → `write_finding(supersedes="FD:…")`：旧判断自动置
   superseded（默认搜索不再返回），时间线仍可审计；跨主体/维度取代会被闸门拒绝
7. **佐证可溯源**：报告引用判断时附 finding_id（`FD:…`），证据引用照旧附 `EV:…`

## 二阶导
不按固定栏目填空。每条是过了删句的一层，附 ≥1 个 `EV:`，并写证伪或「依据不足」。新闻标题和表面句不出现在本段。
数值序列凑满三点时，抄 `acceleration` 里的 d1、d2、a = d2 - d1，不要心算。点数不足只说明加速度算不出，写「二阶导不可计算」和缺的期间，本段仍保留别的算子问出来的那一层。没有新的一层是合格结论。此时不铺水平表。

## 依据
没有新的一层时，本段不铺水平表，只写缺的是哪一层。下面的表只在确有新的一层时写。
- 数据口径说明（主体 ts_code、scope 硅片、period 不可跨口径直比）
- 横向表：营业收入、毛利率、归母净利润（或最接近的利润标尺），列主体 / 数值 / 期间
- 层次：营收细分
- 传导面：指标 / 阶段 / 公司
- 纵向：代表性主体的营业收入时间线

## 判断要点
只留过了删句的二阶导结论，每条附 ≥1 个 `evidence_id`。

## 陷阱
- 先下结论再找证据
- 把「实际−共识」当预期差
- period/单位不一致却做排名解读
- 判断不带 EV:
- 结论只写开放信息、新闻表面、水平值或上台阶
- 为了凑满算子清单而编一层
- 点数不足时整段只剩「二阶导不可计算」
- 判断写不出证伪，也不标「依据不足」
- 期间、口径或单位对不上，仍写 write_finding
- 数值槽已经填满，却编一段假想文档去做语义检索
